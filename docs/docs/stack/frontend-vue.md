# Frontend Stack: Vue

`blacksmith init --frontend vue` generates a Vue 3 application built with TypeScript and Vite, with Nuxt UI for components. It has the same pages, routes, auth flow and API layer as the [React frontend](/docs/stack/frontend), and works with all four backends unchanged.

## Core Technologies

### Vue 3.5

The UI framework. Every component is a single-file component written with `<script setup lang="ts">` and the Composition API. There is no Options API.

### TypeScript (Strict Mode)

Full type safety with strict TypeScript. `npm run build` runs `vue-tsc`, which type-checks `.vue` files as well as `.ts` files, so a type error in a template fails the build. Types for API responses are generated from the OpenAPI schema.

### Vite

The same build tooling as the React frontend:

- Instant dev server startup
- Hot Module Replacement (HMR)
- Optimized production builds
- Path aliases (`@/` maps to `src/`)

### Vue Router 4

Client-side routing with:

- One `routes.ts` per page or feature, composed in `src/router/routes.ts`
- Pages loaded lazily (`component: () => import('./PostsPage.vue')`)
- Route params passed to pages as props (`props: true`)
- An auth guard on `meta.requiresAuth` that waits for the stored session before redirecting
- The shared `Path` enum for type-safe navigation

### Pinia

Client state. The only store generated is the auth store in `src/features/auth/stores/`. Components reach it through the `useAuth()` composable.

### TanStack Vue Query

Server state management:

- Automatic caching and background refetching
- Loading and error states
- Query options and mutations generated from the OpenAPI schema
- `useApiQuery` and `useApiMutation` composables that add DRF error parsing, smart retry and cache invalidation

### Nuxt UI v4 + Tailwind CSS v4

Component library and design system:

- Every interactive element (buttons, inputs, dialogs, menus, alerts) is a Nuxt UI component
- Components are imported explicitly (`import UButton from '@nuxt/ui/components/Button.vue'`). Nothing is registered globally, and `vue-tsc` fails on a component that is used but not imported
- Layout and spacing use Tailwind utility classes; colors use Nuxt UI's semantic classes (`text-muted`, `bg-elevated`, `border-default`)
- The same OpenAI-inspired look and [theme presets](/docs/configuration/theme-colors) as the React frontend
- Light and dark mode that follows the OS, with a toggle in the header
- Iconify Lucide icons (`i-lucide-*`) and the Inter variable font

Nuxt UI runs in plain Vue through its Vite plugin. Nuxt itself is not used.

### Zod

Form validation. Each form is a Nuxt UI `UForm` with a Zod schema. Errors the backend returns for a field are shown under that field.

### VueUse

Generic composables (`refDebounced`, `useLocalStorage`, and so on), so the project doesn't write its own.

### @hey-api/openapi-ts

Generates TypeScript client code from the OpenAPI schema, with the `@tanstack/vue-query` plugin:

- Type definitions
- Zod schemas
- API client SDK
- Vue Query options, mutations and query keys

Components are PascalCase `.vue` files named after the component (`PostCard.vue`). Every other file is kebab-case (`use-posts-query.ts`, `auth-store.ts`).

### Shared with React

The files that contain no framework code are the same in both frontends:

- the API client and token storage
- the auth adapter and its types
- the `Path` enum (`src/router/paths.ts`)
- the shared utils: API error parsing, color mode, dates, `PAGE_SIZE`, site config
- the Terms, Privacy and Support page content

A fix to any of these lands once, in both.

## Key Patterns

### Data Fetching

Use the resource API composables generated by `make:resource`. Pass parameters as a getter, so the query refetches when they change:

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { useProducts } from '@/api/composables/products'

const page = ref(1)
const { data, isLoading, errorMessage } = useProducts(() => ({ page: page.value }))
</script>
```

A plain object is read once: changing `page` afterwards would not refetch.

For lower-level access, import directly from the generated layer:

```typescript
import { productsRetrieveOptions } from '@/api/generated/@tanstack/vue-query.gen'
```

### Mutations

```vue
<script setup lang="ts">
import { useCreateProduct } from '@/api/composables/products'

// Destructure, so the refs unwrap in the template
const { mutate: createProduct, isPending, errorMessage, fieldErrors } = useCreateProduct()

function onSubmit(body: ProductFormData) {
  createProduct({ body }, { onSuccess: () => (open.value = false) })
}
</script>
```

### Form Validation

```vue
<script setup lang="ts">
import { reactive } from 'vue'
import type { FormSubmitEvent } from '@nuxt/ui'
import UForm from '@nuxt/ui/components/Form.vue'
import UFormField from '@nuxt/ui/components/FormField.vue'
import UInput from '@nuxt/ui/components/Input.vue'
import { productSchema, type ProductFormData } from '../schemas'

const state = reactive({ name: '' })

function onSubmit(event: FormSubmitEvent<ProductFormData>) {
  // event.data has passed the schema
}
</script>

<template>
  <UForm :schema="productSchema" :state="state" @submit="onSubmit">
    <UFormField label="Name" name="name">
      <UInput v-model="state.name" />
    </UFormField>
  </UForm>
</template>
```

### Navigation

```vue
<script setup lang="ts">
import UButton from '@nuxt/ui/components/Button.vue'
import { Path } from '@/router/paths'
</script>

<template>
  <UButton :to="Path.Products">View Products</UButton>
</template>
```

Use the shared `TextLink` component for text links, and `router.push(Path.Products)` in script.

## Testing

### Stack

| Package | Purpose |
|---------|---------|
| `vitest` | Test runner (configured in `vite.config.ts`) |
| `jsdom` | Browser environment for tests |
| `@testing-library/vue` | Component rendering and queries |
| `@testing-library/user-event` | User interaction simulation |
| `@testing-library/jest-dom` | DOM assertion matchers |

### Running Tests

```bash
# Run all tests
blacksmith frontend test

# Watch mode
blacksmith frontend run test:watch

# With coverage
blacksmith frontend run test:coverage
```

### Test File Placement

Tests are `.spec.ts` files in `__tests__/` folders next to the code they test:

```
pages/customers/
├── CustomersPage.vue
├── __tests__/
│   └── CustomersPage.spec.ts        # Page test
├── components/
│   ├── CustomerCard.vue
│   └── __tests__/
│       └── CustomerCard.spec.ts     # Component test
```

### Test Utilities

All component tests use `renderWithProviders` from `src/__tests__/test-utils.ts`. It installs the same plugins as `main.ts` (a fresh Pinia store, an in-memory router, Vue Query with test defaults, Nuxt UI) and mounts the component inside `UApp`, so dialogs and menus render:

```typescript
import { screen, renderWithProviders } from '@/__tests__/test-utils'
import CustomersPage from '../CustomersPage.vue'

it('renders the heading', () => {
  renderWithProviders(CustomersPage)
  expect(screen.getByRole('heading', { name: 'Customers' })).toBeInTheDocument()
})

it('renders a card', () => {
  renderWithProviders(CustomerCard, { props: { customer } })
})
```

It returns `user` (from user-event) and the `router`. See the [Testing Guide](/docs/guides/testing) for detailed patterns.

## Linting

`npm run lint` runs ESLint with `eslint-plugin-vue`'s recommended rules and the TypeScript rules. It errors when a component destructures its props in a way that loses reactivity.
